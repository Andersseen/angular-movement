# 1.6 — Layout Motion

**Status: future plan; no implementation started.** Critical milestone. Depends on 1.4 ownership/
settlement and 1.5 snapshot lifecycle lessons. Existing experimental shape earns no automatic promotion.

## Objective

Prove a coherent bounded layout subsystem with correct measurement, interruption and presence/drag composition.

## User story

As a dashboard developer filtering/resizing cards, I can animate reflow and shared handover without
spurious FLIP, lost state, stale snapshots or stuck cleanup when another interaction interrupts.

## Current evidence

MoveLayout measures every Angular render, temporarily clears inline transform and suppresses reads
while animating. Cleanup occurs on natural onDone or null-player return; cancelled player settlement
does not restore that state. SharedLayoutRegistry is a root Map with 300ms logical TTL, pruned only on
access. Tests mock rects and engine; basic browser smoke is not transformed/scrolling/nested geometry proof.
[AUDIT](../AUDIT.md) and [SDD §13](../SDD.md). No external layout usage recorded in 014.

## Scope

Cancellation cleanup, explicit coordinate space, interruption/rebase, batched render phases, scoped
shared identity/snapshots, duplicate/id changes, scroll/viewport/resize invalidation, nested projection,
presence popLayout revival and transform ownership. Compare evolving current API, restricted compatible
contract, wrapper recipe and experimental redesign before graduation.

## Non-goals

Arbitrary CSS 3D/skew/matrix support by assumption, second presence system, browser snapshot replacement,
reorder business state, unconditional ResizeObserver per element, or promotion from demo success.

## Architecture implications

Normalize layout versus visual geometry and include container scroll/ancestor projection. Separate app
baseline from transient projection, avoid inline mutation in a read phase, restore owned origin/projection
on every terminal path. Scoped snapshot-only handover must tolerate incoming/outgoing creation order
without retaining dead Elements indefinitely. This subsystem decides transform composition viability.

## Workstreams

1. Reproduce cancellation/measurement gaps with adversarial browser tests before choosing fixes.
2. Compare geometry/coordinator/native composition/wrapper approaches, including cost limits.
3. Prototype scoped handover and lifecycle; integrate existing presence/drag leases.
4. Pilot two real layout flows; publish support boundaries and graduate/redesign/retain decision.

## Likely code areas

move-layout.directive/shared-layout.registry, transform-state/keyframe-composer/active-player registry,
presence-for popLayout internals, drag integration, layout consumers, targeted e2e and benchmarks.
Experimental input changes need notes/bridge; stable interaction semantics remain opt-in during trials.

## Test strategy

Cancel by drag/set/external WAAPI, destroy mid-projection, zero boxes, id changes/duplicates, shared
creation order, scroll containers/RTL where used, viewport resize, stylesheet/atomic/matrix/ancestor
transforms, nested layouts, CSS resize without Angular render, rapid reflow and hydration baseline.
Assert visual continuity/final boxes and exact origin/style restoration, not only generated frame arrays.

## Docs strategy

Explicit coordinate/support contract, layoutId scope versus View Transition name, wrapper fallback,
list/presence examples, interruption rules and measured unsupported cases. No “magic move everywhere” claims.

## Migration impact

Current layout/id may evolve experimentally in 1.x. Prefer compatible options/bridge where practical;
provide manual wrapper/scoping migrations for transformed structures. Promoting redesigned layout in
2.0 is not itself a justification for a major; default stable composition change may be.

## Performance considerations

Profile 10/50/100 nodes, three nesting levels, read/write/forced-layout counts and idle renders.
Scoped coordinator/observers require measured advantage and bounded caches. Preserve natural layout at rest.

## Accessibility

Reduced motion uses final natural geometry instantly; exiting views do not trap focus. Layout cannot
reorder reading/business state for the app. Hydration establishes snapshot without first-render FLIP.

## Risks

Coordinate errors, scale-distorted child content, stale handovers, cancellation lockout and unbounded
references. Limit contract or keep experimental when proof is incomplete.

## Acceptance criteria

- [ ] Geometry/support limits selected from prototype/browser evidence, not parser assumptions.
- [ ] Every cancellation path restores projection/origin and permits subsequent layout work.
- [ ] Nested/scroll/resize/presence/drag cases pass without double-transform or forced-layout storm.
- [ ] Shared ids are scoped/unique; stale/dead snapshots obey documented lifetime.
- [ ] SSR/hydration/reduced-motion and retained-style behavior pass.
- [ ] Two distinct consumer layout workflows meet correctness/frame/memory gates.
- [ ] Maintainer records graduate/evolve/retain/deprecate/redesign decision and migration plan.

## Evidence required

Dashboard filtering/resizing and interactive card/detail handover from tarball, three-engine visual
traces, owned-resource/heap evidence and migration comparison. Tests of mocked boxes cannot meet this gate alone.

## Maintainer decisions

Scope/id API, supported geometry, wrapper tradeoffs, observer policy and projection order; whether any
stable ownership default needs future major change. No layout graduation until these are resolved.
