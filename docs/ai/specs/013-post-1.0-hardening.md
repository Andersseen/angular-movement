# Spec 013 — Post-1.0 hardening pass

- **Status:** done
- **Created:** 2026-08-28
- **Last updated:** 2026-08-28
- **Breaks public API:** no. Two new exports (`MOVEMENT_STABLE_DIRECTIVES`,
  `MOVEMENT_EXPERIMENTAL_DIRECTIVES`), `MOVEMENT_DIRECTIVES`'s JSDoc corrected (contents/order
  unchanged as a set), `MoveHoverDirective`/`MoveTapDirective`/`MoveFocusDirective` each gain an
  `ngOnInit()`/`playLeave()` pair from implementing `MovePresenceChild` (additive, no signature
  change to any existing member). All additive.
- **Related:** `docs/ai/ARCHITECTURE.md` (multiple new sections), spec 009 (1.0 API freeze —
  reaffirmed here, not reopened), `ROADMAP.md`.

## Problem / motivation

`1.0.0` is out. This is not a feature milestone — it is a focused hardening pass over ten
architectural/product-quality risk areas identified after the freeze: cross-browser confidence,
the stable/experimental package boundary, `MOVEMENT_DIRECTIVES`'s stability consistency, the
Motion Values runtime, `moveTransform()`'s interpolation semantics, smooth-scroll's architecture,
transform ownership/composition, composition test coverage, package positioning, and
documentation of architectural contracts. See `CONTEXT.md`'s non-goals and `BEST-PRACTICES.md` —
nothing here adds a feature, redesigns a stable API, or introduces a new dependency.

## Investigation summary (what was found before any code changed)

Two research passes plus direct reads of `AnimationEngine`, `MoveDragDirective`,
`transform-state.ts`, `move-values.ts`, `WaapiPlayer`/`BaseAnimationPlayer`, `SmoothScrollService`,
`movement.ts`, and `presence.tokens.ts` found:

- **A real, previously-undocumented bug**: `MoveDragDirective.onPointerDown()` snapshots the
  inline `transform` as its base, but if a `moveWhileHover`/`moveVariants`/`moveLayout` WAAPI
  animation is still mid-flight at that instant, the snapshot is stale — and when that animation
  later finishes, `commitStyles()` bakes its own final transform over the attribute, discarding
  whatever the drag wrote in between. A very plausible fast user gesture (hover, then immediately
  drag) triggers it.
- **A real, previously-undocumented gap**: `MoveHoverDirective`/`MoveTapDirective`/
  `MoveFocusDirective` never coordinated with `*movePresence` — their WAAPI animations could keep
  running (and racing the real leave animation) after an exit had already started.
- **A real, previously-undocumented gap**: `moveTransform()`'s `interpolateOutput` silently falls
  through to a discrete midpoint switch for mismatched units (`"10px"`→`"2rem"`), non-numeric
  strings (`"red"`→`"blue"`), and embedded transform functions
  (`"translateX(0px)"`→`"translateX(100px)"`) — with no warning. A caller expecting smooth output
  gets an unannounced hard jump.
- **A real, previously-undocumented accessibility bug**: `SmoothScrollService` has no keyboard or
  native-scroll listener at all. Its RAF lerp loop unconditionally writes `scrollTop` toward a
  target that only wheel/touch update, so native keyboard scrolling (arrows, Page Up/Down,
  Home/End, Tab-triggered focus-into-view) gets fought and effectively broken while
  `[moveSmoothScroll]` is active.
- **`MOVEMENT_DIRECTIVES`** (all 21) is itself tagged stable but was never stability-pure — 5 of
  its members are individually experimental, with no aggregate for consumers who want a
  stability-pure spread.
- **Motion Values**: `moveSpringValue()` runs one independent RAF loop per call, confirmed by
  tracing the source — no shared scheduler exists.
- **Experimental entry point**: `ng-package.json` is still single-entry (`entryFile` only, no
  `lib.secondaryEntrypoints`), and the current experimental surface still needs no dependency
  stable consumers shouldn't pay for.
- **E2E**: `playwright.config.ts` had exactly one project (Chromium); no cross-browser coverage
  existed at all.
- **Package metadata**: `projects/movement/package.json`'s `description`/`keywords` undersold the
  library relative to what it now does (variants, presence, gestures, motion values, layout,
  zoneless, SSR).

## Proposed solution

A decision-and-hardening pass, scoped by area:

### 1. Cross-browser E2E

New `e2e/cross-browser.spec.ts` (12 tests: `[move]`, enter/leave, presence, variants,
hover/focus/tap, drag, layout, scroll, SVG, Motion Values, reduced-motion), run on
Chromium+Firefox+WebKit via `playwright.config.ts` projects scoped with `testMatch`. The
comprehensive suite (`demos.spec.ts`, `docs.spec.ts`, `home.spec.ts`, new `composition.spec.ts`)
stays Chromium-only. `motionState`/`settledMotionState` extracted from `demos.spec.ts` into
`e2e/motion-state.ts` so the new files reuse them instead of duplicating.

### 2. Experimental entry point

Reaffirmed, not reopened: no secondary `angular-movement/experimental` entry point. Documented the
re-audit and its evidence in `ARCHITECTURE.md` and both READMEs.

### 3. `MOVEMENT_DIRECTIVES` stability

Additive split in `lib/movement.ts`: new `MOVEMENT_STABLE_DIRECTIVES` (16) and
`MOVEMENT_EXPERIMENTAL_DIRECTIVES` (5), with `MOVEMENT_DIRECTIVES` redefined as their
concatenation (same 21 members as a set; JSDoc corrected to say so explicitly). Locked down by a
new test in `movement.spec.ts`.

### 4. Motion Values profiling

New benchmark tests in `move-values.spec.ts` at 1/10/50/100 concurrent springs, measuring RAF
registration growth (bounded, not exact, against a same-test baseline to tolerate Angular's own
zoneless CD scheduler also using `requestAnimationFrame`) and teardown leak-freedom. Conclusion:
architecture acceptable, no scheduler introduced.

### 5. `moveTransform()` interpolation

`interpolateOutput` refactored into an ordered `VALUE_INTERPOLATORS` list (number,
matching-unit-string, implicit discrete fallback) in `move-values.ts`. The discrete fallback now
calls `movementWarn()` once per distinct mismatched pair. Public signature unchanged.

### 6. Smooth scroll

Kept in the main entry point, still experimental (documented decision, no split). Fixed the
keyboard/native-scroll bug: a new `scroll` listener in `SmoothScrollService` detects a `scrollTop`
change the service didn't itself write (via `#lastAppliedY`) and resyncs instead of fighting it.

### 7. Transform ownership and composition

New internal `engines/active-player-registry.ts` (`WeakMap<Element, AnimationControls>`,
not barrel-exported). `AnimationEngine.play()` registers every player it creates.
`MoveDragDirective.onPointerDown()` cancels whatever is registered for its host before reading the
base transform — the explicit ownership rule: **drag owns the transform exclusively from
`pointerdown` forward**. `MoveHoverDirective`/`MoveTapDirective`/`MoveFocusDirective` now optionally
inject `MOVE_PRESENCE_PARENT` and implement `MovePresenceChild`, cancelling their own player once a
presence exit begins. Documented in full in `ARCHITECTURE.md`.

### 8. Composition/adversarial tests

New `e2e/composition.spec.ts` (Chromium): drag+hover mid-transition, drag+tap, presence-for rapid
remove+add+shuffle, presence destroy-mid-transition + reduced motion, scroll-linked
moveScroll→moveTransform→moveSpringValue chain, rapid SVG icon+variants toggling. Two demo pages
gained minimal markup to make real combinations testable: `drag.page.ts` (added
`moveWhileHover`/`moveWhileTap` on the same card) and `scroll.page.ts` (added a
`moveTransform`+`moveSpringValue` element driven by the scroll directive's own `progress` signal
via its `exportAs`). Targeted unit tests added alongside for the underlying mechanism
(`active-player-registry.spec.ts`, plus cases in `move-drag`/`move-hover`/`move-tap`/
`move-focus.directive.spec.ts`).

### 9. Package positioning

`projects/movement/package.json` description/keywords refreshed to cover signals, presence,
variants, gestures, motion values, layout, zoneless, SSR. Both READMEs' opening pitch extended
with the same missing concepts (neither used "Framer Motion for Angular" framing — confirmed by
grep, so no reframing was needed). Root `package.json` (private, unpublished) and GitHub's repo
description setting were left alone — out of scope, the latter flagged for the user to action
directly since it's a shared, externally-visible setting.

### 10. Documentation

`docs/ai/ARCHITECTURE.md` gained: "Browser support and testing strategy", "`MOVEMENT_DIRECTIVES`
aggregate policy", reaffirmed "Experimental compatibility policy", "Transform ownership and
composition", "Motion Values runtime model", "`moveTransform()` interpolation contract", and
"Smooth-scroll architectural status". Both READMEs updated to match. `docs/ai/STATE.md` and
`CHANGELOG.md` updated per Phase 6.

## Out of scope

- No new directives, presets, or motion primitives (timelines, reorder, route transitions, View
  Transition API, color interpolation).
- No redesign of any stable API. `moveTransform()`'s public overloads, `MOVEMENT_DIRECTIVES`'s
  contents, and every directive's selector/inputs are unchanged.
- No secondary `angular-movement/experimental` entry point — reaffirmed, not built.
- No package split for smooth scroll.
- No shared/batched RAF scheduler for Motion Values — measured, not justified.
- No color interpolation in `moveTransform()` — the architecture now supports adding one later, but
  none was added now.
- No channel-level merge in the transform compositor (e.g. re-reading only non-owned channels at
  WAAPI commit time) — the narrower, lower-risk drag-preemption fix was chosen instead; see
  "Remaining risks" below for when the broader fix would be worth revisiting.
- No rewrite of `AnimationEngine`/`WaapiPlayer`/`SpringPlayer`/`keyframe-composer.ts`.
- No `1.x` version bump or release — implemented on the branch, released as its own later step.

## Follow-ups (out of scope, noted for later)

- Full channel-level merge at WAAPI commit time (re-reading only non-owned transform channels
  live instead of drag unconditionally preempting) would generalize the transform-ownership fix
  beyond drag specifically, at real implementation and testing cost in `keyframe-composer.ts`. Not
  pursued now — the drag-preemption fix covers every case found during this pass, and
  `keyframe-composer.ts`/`transform-state.ts` are exactly the "engines/ is high-risk" files
  `SDD-WORKFLOW.md` calls out for extra caution. Revisit only if a new composition bug surfaces
  that the current registry doesn't cover.
- `moveTransform()` color interpolation: the `VALUE_INTERPOLATORS` list is now the extension point
  for it, but no color interpolator was added — no concrete request for one exists yet.
- GitHub's repo description (an external, shared setting, not a file in this repo) was not
  updated — flagged for the maintainer to action directly if desired.
- The scroll/composition demo pages (`drag.page.ts`, `scroll.page.ts`) could use a short doc note
  explaining _why_ they combine directives the way they do (composition examples, not just demos)
  — a nice-to-have, not done here.
