# Spec 021 — 1.6 layout motion and shared-element reliability

- **Status:** in-progress
- **Created:** 2026-10-31
- **Last updated:** 2026-10-31
- **Breaks public API:** no (one additive experimental input, `moveLayoutScope`)
- **Related:** specs 013, 020; `docs/v2/plans/1.6-layout.md`; baseline `main` = `ed9bacb`, source 1.4.0

## Problem / motivation

`moveLayout` passed its demo and mocked unit tests, but no test ever changed layout _while_ a FLIP
was running, scrolled, nested two layout hosts or reused an id in two regions. Reading the code
showed several gaps; each one below was then reproduced in a real browser before being fixed.

This milestone adds no animation, directive or preset. It makes the existing experimental layout
subsystem predictable, and records the supported and unsupported geometry.

Hypotheses that did **not** reproduce: forced-layout storms (measured: 1 rect + 1 computed-style read
per element per pass), idle polling (0 reads/animations in 1 s at rest), and drift under repeated
drag + reflow (offset held exactly over 10 reflows, packed).

## Solution

1. `engines/layout-geometry.ts` (internal): measure the **natural box** — the viewport rect with the
   element's own 2D transform inverted from _computed_ style (translate, rotate, scale, transform,
   transform-origin; running animations included), ancestors' scroll offsets added, and any
   mid-FLIP layout-host ancestor undone first. No string parsing of arbitrary CSS transforms.
2. `MoveLayoutDirective`: measure every pass (including mid-FLIP); a FLIP in flight is replaced
   (cancelled) by a new one that starts from the old natural box projected through the current
   animated transform; a change that lands exactly on the start retires the old FLIP; the borrowed
   origin is saved once and restored on every terminal path (finish, cancel, replace, disable,
   destroy); late settles after destroy are ignored; reduced motion re-read per pass.
3. `SharedLayoutRegistry`: key `scope + id`; entries hold a box and an opaque owner token, never an
   `Element`; ≤128 entries; 300 ms lifetime unchanged; dropped on viewport resize; scroll handled by
   the scroll-adjusted boxes. New experimental input `moveLayoutScope`.
4. Demo `/demos/layout`: per-item `moveLayout` (the old demo put it on the container, which scaled
   its children), scenarios Reflow / Shared element / With presence, a Nest toggle.
5. Packed-consumer fixture: dashboard, card/detail and a layout+hover+drag element, run on Angular
   21 and 22 from the tarball.

## Decisions

- **No ResizeObserver.** Layout is measured on Angular render passes only. A CSS-only size change
  (media query, container resize with no Angular render) is not observed; the contract says so.
  No consumer evidence justifies one observer per element.
- **No scheduler/batching.** Cost is 1 rect + 1 computed-style read per element per pass, all in the
  `earlyRead` phase and all writes in `write`; measured numbers show no regression worth a
  scheduler.
- **Scope as an input, not a directive.** `moveLayoutScope` on the layout host is additive,
  experimental, and needs no new export, token or aggregate entry. Without it nothing changes.
- **Stays experimental.** Unsupported geometry is bounded and listed, not claimed.

## Out of scope

New animations/presets, a reorder/DnD API, a group/sequence DSL, router transitions, gesture
redesign, a LayoutGroup clone, stable promotion of layout, publishing (Release Please owns it).
